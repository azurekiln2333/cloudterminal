# 三端流程与体验打通(账号 + 配对 + 自动更新)

## Goal
把现在各自为政的 服务端 / 电脑端 / 手机端 串成一条连贯流程:**登录一次账号,电脑和手机自动互相看见,点一下就能用**。

## 问题(用户原话:流程割裂、页面割裂,体验很不好)
**流程割裂**
- relay 已有 OAuth2 账号 + 多对多设备绑定(`10-13-relay-multitenant`),但手机端、Windows 端都没有登录/绑定/设备列表界面,仍走旧的设备密钥配对。账号能力对用户等于不存在。
- Windows 配对页写“手机扫码”,手机端却没有扫码,只能粘贴链接或输 8 位短码 + 服务器地址。
- 电脑端要先配置中继地址,手机端再单独填一遍同样的地址。
- 网关 `azurekiln-oauth2` 没有 RFC 8628 设备授权端点,只有授权码 + PKCE。

**页面割裂**
- 手机端:未配对时是 `PairScreen`,配对后是 `HomeScreen`,内部另起一个嵌套 Navigator;会话 / herdr / 终端 / codex 各自独立页面,靠多处 `Navigator.push` 跳转,没有统一的导航骨架。
- Windows 端:总览 / 工具 / 会话 / 配对 / 设置 五个并列页,“配对”独占一页,与首次使用流程脱节。
- 两端各自一份 `app_theme.dart` 与组件,没有共用的信息架构。

## 目标流程
1. 电脑端启动服务 → 自动打开本机 Web 绑定页(`http://127.0.0.1:<port>`),点“登录并绑定” → 网关登录 → 本机自动绑定到该账号。同一页也显示二维码/短码给手机备用。
2. 手机端启动 → 点“登录” → 系统浏览器登录网关 → 回到 app,首页列出“我的电脑”(在线状态),点一台进入会话。
3. 登录回调统一落在 relay 的网页上,app / 本机页面按 state 轮询拿结果,**不依赖 app 自定义 URL scheme**(鸿蒙/Windows 无需注册回跳)。
3. 账号不在手边/访客场景:保留电脑端二维码 / 短码 / 局域网发现作为备选,走现有 `pair_code` 同意机制绑定到账号。
4. 服务端:镜像发布后 watchtower 自动更新。

## 子任务
- `11-02-account-auth` 手机端 + Windows 端接入账号登录与设备列表(调用现有 `/api/v1`)
- `11-02-pairing-simplify` 配对改为“账号下绑定”,扫码 / 短码 / 局域网发现作为备选
- `11-02-ux-unify` 统一信息架构与导航骨架,再统一视觉 token
- `11-02-server-autoupdate` watchtower 自动更新

## 依赖顺序(写在子任务里)
account-auth → pairing-simplify → ux-unify(导航骨架依赖前两者确定页面集合);server-autoupdate 独立。

## 验收
- [ ] 新用户:电脑登录一次 + 手机登录一次,手机列表出现该电脑,点击进入会话;全程无需输入服务器地址或密钥
- [ ] 手机端只有一个导航骨架(底部导航:电脑 / 会话 / 设置),不再有未配对/已配对两套割裂入口
- [ ] Windows 端首次启动自动进入登录引导,配对不再是独立一页
- [ ] 旧的设备密钥配对仍可用(向后兼容)
- [ ] Dart / Node 现有测试通过

## 约定与待定
- OAuth 客户端信息由运维在 relay `.env`(`OAUTH_ISSUER/CLIENT_ID/CLIENT_SECRET/REDIRECT_URI`)配置,不属于本任务。
- 手机端怎么知道 relay 地址:扫码/短码/本机 Web 页给出;登录路径下默认地址待定。
- 鸿蒙相机扫码插件可用性待调研(扫码仅为备选路径)。
