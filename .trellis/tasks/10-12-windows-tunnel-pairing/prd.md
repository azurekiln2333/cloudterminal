# Windows Flutter(MD3) 连接助手 + 工具绑定 + 中继/扫码配对

## 背景

CloudTerminal 目前可用，但有两类门槛：

1. **连接门槛**：电脑端要手工跑 `start.cmd` / CLI 并回答向导（连接方式、中继地址、
   注册密钥、目录）；手机端 `PairScreen` 要手填服务器地址 + 8 位配对码；还要抄地址。
2. **工具绑定门槛**：用户希望在这个 Windows 程序里直接**绑定和查看**自己实际用的
   工具 —— Herdr、Codex、Claude Code（cc）—— 并**实时读取输出流**。

用户诉求原话（两次）：

- *"让 pi 尽量做到降低匹配连接门槛。可以做一个简易程序在 Windows 上跑，Windows 一个、服务端负责隧道、手机连接？"*
- *"windows 小程序的话，看看能不能开个 flutter 工程来跑。windows 小程序是负责绑定 herdr、codex、cc 这些工具的，能实时读取输出流这样？flutter 界面按标准化 md3 风格来做。"*

即：**一个 Flutter Windows(MD3) 客户端，负责连接/配对 + 工具发现/绑定/会话选择 +
实时输出展示；服务端仍是现有中继；手机可连上并控制。**

## 工具真实能力（实测，2026-10-12；见 research/tool-sessions-2026-10-12.md）

必须先说清楚：**无法读取任意已运行 TUI 进程的 stdout**。三个工具都只有"由该工具
自身 daemon/server 管理的会话"才可程序化接入。因此客户端区分两类绑定：

- **管理型（managed）**：由客户端启动/驱动 → 拿到真事件流。
  - Codex：`codex app-server` JSON-RPC（`ThreadStart`/`TurnStart` +
    `AgentMessageDelta`/`CommandExecOutputDelta` 通知）；本机 daemon 已在运行。
  - Claude Code：`claude -p --output-format stream-json --verbose` NDJSON 流，
    或 `claude --bg` + `claude logs <id>`。
- **只读型（read-only）**：对已存在会话做列表/读取，不能接管交互。
  - Codex：`ThreadList`/`ThreadRead`（daemon 历史）。
  - Claude：`claude agents --json` + `claude logs <id>`（最近输出快照）。
  - Herdr：`pane read`（屏幕文本，**轮询**，Herdr CLI 无变更推送）。

**硬规则**：UI 必须为每个绑定显示来源标签（真流 / 只读历史 / 轮询+刷新间隔）；
**不得把轮询或历史快照标成"实时输出流"**，不得用演示数据冒充绑定成功。

## 现状可复用性（已核实）

| 能力 | 现状 | 复用度 |
| --- | --- | --- |
| Agent 主动外连中继（无需入站端口/NAT） | `RelayLink` 已经是 outbound `ws`/`wss` 长连接 | **直接复用** |
| 中继认证 + 路由 | `relay.ts`：agent 注册（可选 `relayKey`）、客户端交换一次性配对码、常量时间比较、按 IP 限流 | **直接复用** |
| 一次性配对码 | `link.ts` 生成 8 位 `PAIR_CODE_ALPHABET` 码，`relay.ts` 保存并可交换 | **直接复用**，需要增加"扫码"通道 |
| 配对后凭据持久化 | agent `config.ts` 持久化 `agentId/secret`；手机 `AppStore` 持久化 pairing | **直接复用** |
| 断线重连 | `RelayLink` 有心跳 watchdog + 指数/定时重连；`RemoteController` 重连后刷新 | **直接复用** |
| 局域网/隧道模式 | `--local-relay` + `--public-url`（Tailscale/Cloudflare 隧道） | **直接复用**，作为无需公网服务器的选项 |
| 桌面共享终端 | `--terminal` + `local-terminal.ts` | **直接复用** |
| Herdr 接入 | 上一个任务已完成（bridge + 手机 UI） | **直接复用** |

结论：**不需要重写服务端**。缺的是"外壳 + 配对握手简化"：

- 缺一个 Windows 上双击即开、有可见状态（在线/离线、手机是否已配对、Herdr 是否可用）的客户端；
- 缺一个"中继 = 部署者一次配置，用户零配置"的分发方式（把 relay 地址与注册密钥烘焙进打包配置/短码，而不是让每个用户手填）；
- 缺手机端"少填参数"的入口：扫码或短码。

## 目标

### G1 Windows Flutter(MD3) 客户端（双击即用）

- **独立 Flutter Windows 工程**（用户明确要求），不与手机工程混编；手机工程保持可用。
- UI 用**标准 Material 3**：`useMaterial3: true`、`ColorScheme.fromSeed`、标准
  `NavigationRail`/`NavigationDrawer`、`Card`/`ListTile`/`Chip`/`FilledButton`、
  统一 `ThemeData` 与排版；不另造视觉体系。
- 双击即启动（发布版 `cloudterminal_win.exe`），不需要命令行窗口，不需要回答向导
  （首次可从打包配置 `bootstrap.json` 或短码自动拿到中继地址）。
- 首屏一眼看清：中继在线状态、手机配对状态、各工具绑定状态（Herdr/Codex/Claude）。
- 出错给可操作中文提示（未装 Node/工具、中继不可达、密钥不匹配、工具未登录、
  目录无效），不打印长堆栈。

### G1b 工具发现 / 配置 / 绑定 / 会话选择 / 实时输出

- **发现**：探测 `herdr`、`codex`、`claude` 是否存在、版本、是否已登录/daemon 在跑；
  缺失时显示安装指引，不假装可用。
- **绑定**：对每个工具可"绑定"一个来源，并显示来源类型：
  - Codex：连接 `codex app-server`（stdio 或已运行 daemon 的 control socket），
    列出线程（`ThreadList`）与实时事件。
  - Claude Code：`claude -p --output-format stream-json` 启动的会话为真流；
    `claude agents --json` + `claude logs` 为只读。
  - Herdr：`herdr workspace/agent` 列出工作区与 agent；`pane read` 轮询屏幕。
- **会话选择**：列表中选一个会话/pane 查看；区分"由助手启动"与"已存在只读"。
- **实时输出展示**：
  - 真流：增量追加，自动滚动，支持暂停/继续；
  - 轮询源：按固定间隔刷新，UI 明确标注"轮询 + 间隔"；
  - 正确处理中文（UTF-8，勿按字节截断）、ANSI（可选终端渲染或去色）、
    持续高频输出（限流/截断旧行，保持 UI 流畅）。
- **不重启、不重复启动、不丢弃会话**：绑定不改动用户既有 daemon/会话；不因绑定
  而 `kill`/`respawn` 用户会话；不新起第二个 daemon 抢同一历史。

### G1c 连接/配对（沿用低门槛方案）

- 客户端显示**二维码**（内含中继地址 + 一次性配对码）与**短码**，可刷新。
- 手机扫码（或短码）后一次点击完成配对；保留手填兜底。
- 二维码内容 `cloudterminal://pair?relay=…&code=…`，10 分钟一次性、刷新作废，
  **不含长期密钥**。

### G2 服务端中继隧道（部署者一次配置）

- 中继继续由部署者（就是用户自己，或未来某人）用现有 `server/` + Compose 部署，**不新增付费资源、不擅自部署公网服务**。
- 新增"分发配置"概念：中继地址（和可选注册密钥）可以烘焙进客户端分发包或通过短码下发，使普通用户零配置。
- 明确安全边界：中继不解析会话内容；手机仍必须有一次性配对码才能拿到 agent 凭据；注册密钥只限制"谁能把 agent 注册到我的中继"，不能替代配对码。

### G3 手机扫码 / 短码配对

- 手机 `PairScreen` 增加**扫码**入口：扫电脑显示的二维码，自动得到 `relayUrl + agentId + 一次性码`，用户点一次"连接"即可。
- 保留**短码**入口（无摄像头/权限时）：手输 8 位码，中继地址来自扫码结果或分发包/上次记录，不必再填地址。
- 保留现有"手工填地址+码"和"手工填 agentId+secret"作为兜底，不删除。
- 扫码后如果中继地址与上次不同，要明确提示"将连接新的服务器"。

### G4 安全（用流程解决，不牺牲认证）

- 不提供"无认证远控"换低门槛。降低的是**操作步骤**，不是**认证强度**。
- 一次性配对码仍是进入的唯一凭据；二维码 = 地址 + 一次性码，等价于现在的配对横幅，只是免手抄。
- 二维码/短码有 TTL（沿用 10 分钟）且一次性；刷新即作废旧码。
- 不做"永久二维码"。断线重连用的是已配对的持久凭据（agentId+secret），日常不需要再扫码。
- 提供**取消授权**：手机端"移除这台电脑"（已有 unpair）与电脑端"重置配对身份"（`--reset-pairing` 语义，客户端里可点）。
- 客户端把凭据保存在用户私有目录、权限收紧（复用 `config.ts` 的 0600 行为）。
- 不硬编码密钥；分发包里的中继地址是公开信息，注册密钥若需内置必须可被用户替换并可清空。

### G5 首次配置 / 断线重连 / 错误提示

- 首次：如果分发包带中继地址，客户端直接连；否则提供一步"填地址或扫部署者给的短码"。注册密钥仅在**部署者专用分发**里预置，且必须可覆盖。
- 断线：中继不可达时窗口显示"离线（重试中，第 N 次）"，自动重连，不要求用户操作；恢复后自动回在线并保持已配对。
- 错误分类展示：未安装 Node → 给下载指引；中继拒绝（密钥错误）→ 明确"注册密钥不对"；端口占用 / 目录无效 / Herdr 缺失 → 各自的可行建议。

## 非目标（不做）

- 不读取任意已运行 TUI 进程的 stdout（技术上不可行）。
- 不重启/接管用户已有的工具会话来完成绑定；不新起重复 daemon/server。
- 不做端到端加密（沿用现有边界）。
- 不做自动更新/安装器签名/商店分发。
- 不擅自部署公网服务、不产生付费资源、不申请域名/证书。
- 不改中继协议的核心路由语义（只做加法：分发配置、短码、二维码内容）。
- 不把手机工程改成桌面工程（新建独立 Windows 工程）。

## 已定与仍需确认

已定（用户已授权或本轮自行决定）：

- 客户端形态：**独立 Flutter Windows 工程**（用户明确要求），标准 MD3 UI。
- 工具接入按"管理型真流 / 只读型"分层，并在 UI 标注来源。
- 手机端保留手填并增加扫码/短码；不删除现有路径。

仍需确认（不阻塞本轮实现，但影响分发包）：

1. **中继由谁部署**：是否已有/计划公网服务器 + 域名？决定"烘焙地址"还是额外做
   "邀请短码下发"，以及是否把 Tailscale/Cloudflare 隧道当默认。
2. **注册密钥是否内置分发包**：默认**不内置**（改用短码/一次性邀请码）。
3. **手机是否允许新增二维码扫描库**（如 `mobile_scanner`）：不允许则用"粘贴二维码
   内容"兜底；Windows 端展示二维码不需要新依赖（自绘/内联）。

## 验收标准

1. `apps/cloudterminal_windows`（或 design.md 确定的路径）能 `flutter build windows`
   成功，并能在本机 `flutter run -d windows` 启动出 MD3 窗口。
2. 客户端首屏显示：中继在线状态、手机配对状态、三个工具（Herdr/Codex/Claude）
   的发现结果（版本 + 可用/原因）。
3. 能看到配对二维码与短码；手机扫码或短码后一次点击完成配对（真机或模拟验证）。
4. 工具绑定：至少 Codex 与 Claude 各有一个"管理型真流"路径可启动并增量显示输出；
   只读路径（`claude agents --json`/`ThreadList`/Herdr `pane read`）能列表并显示，
   且 UI 标签正确标注"只读"或"轮询 Ns"。
5. 输出渲染正确处理中文（UTF-8）与 ANSI，长时间高频输出下 UI 不卡死（有界缓冲）。
6. 绑定/查看不重启、不 kill、不 respawn 任何用户既有会话/daemon；不新起重复 daemon。
7. 配对码/二维码 10 分钟过期、一次性；刷新后旧码失效。
8. 断线自动重连，UI 显示离线与重试；错误均有可操作中文提示。
9. `cd server; npm run check; npm test` 与两份 Flutter 工程的 `flutter analyze`/
   `flutter test` 均通过；跨层测试覆盖配对 URI 与至少一种工具事件映射。
10. 不新增公网部署、不产生付费资源；仓库不含硬编码长期密钥。
11. 原有手机工程与既有未提交改动不受影响。
